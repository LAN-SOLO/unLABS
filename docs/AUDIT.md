Hinweise für Spieler: Solange die Mac-App nicht notarisiert ist, kann macOS beim ersten Start warnen (Rechtsklick → „Öffnen“, ab macOS 15 Systemeinstellungen → Datenschutz & Sicherheit → „Dennoch öffnen“); Windows zeigt bis zur Signierung SmartScreen („Weitere Informationen“ → „Trotzdem ausführen“). ### 4. Offene Punkte (priorisiert)

1. Notarisierung der Mac-App (Developer-ID-Signatur ist bereits aktiv; es fehlen `hardenedRuntime`, Entitlements, Signatur der gebündelten Binaries mit `--options runtime` und `notarize`); Windows: OV/EV-Zertifikat oder Azure Trusted Signing. Danach Auto-Update (`electron-updater`) mit Signaturprüfung.
2. Wirtschaft serverautoritativ machen (W3, W6, W7): Claim-RPCs pro Belohnung, Client-Schreibrechte entziehen, atomare Claims.
3. Test der Windows-Installer auf echter Hardware (Spiel + undevbook).
4. GoTrue für Windows reproduzierbar bauen und Hash pinnen (D16).
5. Desktop: `asar` + Fuses nach Umstieg auf `utilityProcess`/Next-Standalone (D15); Service-Keys kürzer laufen lassen.
6. CSP mit Nonces statt `unsafe-inline`/`unsafe-eval`; geteilte Rate-Limits; Wallet-Challenge mit Nonce + Domain.
7. Metaplex-Abhängigkeiten aktualisieren (letzte 2 moderaten Audit-Funde).
8. Beim Umstieg auf pnpm ≥ 10 die Sicherheits-`overrides` aus `package.json` nach `pnpm-workspace.yaml` verschieben (neuere pnpm-Versionen ignorieren das `pnpm`-Feld; das Projekt nutzt pnpm 9.15, dort greifen sie — im Lockfile verankert).

- **Web/UI:** Next.js 16 (App Router, Server Actions, Middleware), React 19, Tailwind CSS 4, Radix UI, lucide-Icons, `motion` (undevbook), Hash-Router (undevbook), Vite 8 (undevbook).
